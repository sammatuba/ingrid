The view is rendered from a saved `ProbeBundleArtifact`: composed label, fired rule and reason,
atomic answers with per-form tops and (for nouls) the un-negated probability the receipt compares,
the stability receipt with its thresholds, the instability line, the escalation, provider/model
metadata with both digests, and the passages the probes refer to. Every value is written with
`textContent`; no field is parsed as markup. A saved bundle is presented as a proposal that changes
no accepted value.

`bundle_available` (the frozen sibling of `model_available`) is read from the workspace projection.

manual review, the dispositions and the cited brief are untouched. True: the button saves a bundle
through the frozen route and saved `probe_bundles` entries for the current task are rendered.
No model is called by the default app; `model_available` and `bundle_available` are false on the
local walkthrough until CORE-2 wires the port.

## Fixture provenance (no invented case facts)

The two fixtures embedded in `app.js` were generated by the real S1 functions in
`src/judgment/bundle.py` (`render_bundle`, `compose`, `receipt`) from a contract-valid
`CompiledTask` (h0.v1, built with `make_record`, so the record validator accepted it) whose state
is working-paper appendix A: `unit:fictional-U3`, field `commercial_availability_from`, cutoff
`2026-09-14T00:00:00+08:00`, mapping candidates U3/U2, and the appendix A passage quote.

* `appendix-a`: label `challenges`, rule `milestone_mismatch: …`, atomic
  `q1 unit:fictional-U3, q2 testing, q3 same, q4 yes, q5 no, q6 no, q7 yes, q8 challenges`,
  `flip_rate` `q3 0.25` and the rest `0.0`, `polarity_gap` `q4 0.06`, `q7 0.11`, `unstable false`,
  `escalation none`, thresholds at their initial values — every printed appendix A value.
* `unstable`: the same task and answers with Q2 flipping on two of four forms, which is the
  instability case named in the intent's acceptance table: `unstable true`, `unstable_questions
  ["q2"]`, label `insufficient`, reason `UNSTABLE`, escalation
  `gemini_interpretation_and_manual_review`.

Where appendix A prints a number, the fixture carries it. Where it prints a rate but not the
underlying form values, the fixture carries the minimal value that rate implies (the f1 negated
answer is the complement of the f0 value, so `polarity_gap` is exactly 0.06 and 0.11; the one
differing Q3 top sits on the option-order form f1, which is what `flip_rate 0.25` means); f2 and
f3 repeat f0; every choice form answers its modal option at 1.0, which is the fixture's encoding of
"this form selected that option" and not a model output. Appendix A's date value cannot be a
h0.v1 `quantity` (decimal strings only), so the fixture task encodes it as the compact decimal
`20261003` with unit `date`; the probe view never renders that field and the composition reads
`input_field`. The escape carrier is the fixture passage
`<script>window.probeExecuted=true</script>`, in the same spirit as the synthetic case's own
`<script>window.sourceExecuted=true</script>` source line.

Generator and checks live outside the repository tree, under ignored `.local/ui-1/`
(`make_probe_fixtures.py`, `verify_probe_view.py`). They are the source of the two commands below.

The fixture JSON is embedded in `app.js` rather than served as a file because the only asset route
is `GET /assets/{name}` with a frozen whitelist (`app.js`, `style.css`), the API routes are frozen,
and the shared fixture path `tests/fixtures/probe-bundle/` belongs to the EVAL lane. UI-5's browser
check can inject the same fixtures into a `/workspace` response instead of previewing them.
